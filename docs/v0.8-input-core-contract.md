# V0.8 Input Core Contract

## Goal

Fix direct note input at the root. The editor must make it obvious where the
next note will be placed, then place the note at that exact musical location.

## Visual Contract

- The active input slot is a rounded blue focus box centered on the note column.
- The ghost notehead sits inside the slot box, not on its left or right edge.
- The slot box keeps a readable minimum width for all supported durations.
- Short durations may make the measure wider, but they must not make the active
  slot collapse into a thin line.
- The ghost note uses the same x column as the active slot.
- Ledger lines belong only to the ghost notehead and must never form a long
  ladder through another staff.
- Hovering in the dead zone between treble and bass in a grand staff should not
  switch staff accidentally.
- Empty measure slot hover should feel stable before any note is placed.
- After click, the rendered note/chord column must match the ghost column.

## Rhythm Contract

- Snapping is duration-aware:
  - whole = 4 beats
  - half = 2 beats
  - quarter = 1 beat
  - eighth = 0.5 beat
  - sixteenth = 0.25 beat
  - thirty-second = 0.125 beat
- Generated rests can fill the internal rhythm model, but generated rests must
  not drive the visible slot box or event count.
- Dynamic measure width may respond to extra rhythm boundaries, but input slot
  visual width is a UI affordance, not the literal rhythmic duration width.

## Pass Cases

- Hover quarter, eighth, sixteenth, and thirty-second in treble measure 1.
- Place two eighth notes consecutively; cursor advances to the next slot.
- Place a sixteenth after two eighth notes; the measure may widen but the slot
  remains readable.
- Hover between treble and bass; no ghost appears unless pointer is clearly in a
  staff input band.
- Hover bass staff; bass slot and ghost appear only on bass.
- Hover high/low ledger positions; ledger lines are short and localized.
- Sidebar event count equals user-visible events only.

## Browser Evidence Required

Every checkpoint that changes input behavior must include screenshots for:

- Hover first slot.
- After two short notes.
- Hover shortest supported duration.
- Hover between staves.
- Hover bass staff or bass ledger.

## Checkpoint Rule

Do not create a checkpoint unless:

- Focused unit tests pass.
- Browser screenshots match this contract.
- Any remaining mismatch is explicitly documented before continuing.
