# v0.5 User Acceptance QA

This document defines the product-level gate for the next SheetLab milestone.
Automated tests are necessary, but this QA must also be completed in the browser
with real user-style interactions.

## Rules

- Do not use devtools or direct model editing to create the acceptance scores.
- Do not pass a step if the browser flow requires hidden horizontal scrolling for
  basic note entry.
- Do not pass a step if notes, stems, or ledger lines are visually clipped in the
  editor or exported PDF.
- Do not pass PDF export if it opens the browser print dialog. Export must return
  a real PDF file from the app/backend.
- Commit a git checkpoint only after the step-specific tests and browser QA pass.

## Acceptance Song 1: Treble Melody

Score setup:

- Score type: Treble only
- Page size: A4
- Tempo: 96
- Title: Untitled Piano Exercise is acceptable for this milestone

Final notes:

```txt
Measure 1: E4 quarter, D4 quarter, C4 quarter, D4 quarter
Measure 2: E4 quarter, E4 quarter, E4 half
Measure 3: D4 quarter, D4 quarter, D4 half
Measure 4: E4 quarter, G4 quarter, G4 half
```

Required user mistakes during creation:

- Enter one wrong pitch, then repair it by dragging the note.
- Enter one extra note, then delete it through the notation UI.
- Skip one middle note, then use Insert mode/cursor to add it without deleting the
  following notes.

Pass criteria:

- The melody can be created from an empty score by browser interactions only.
- The final note order matches the expected score.
- Playback follows the final order.
- Exported PDF contains the final melody without clipped notes.

## Acceptance Song 2: Piano Grand Staff

Score setup:

- Score type: Grand staff piano
- Page size: A4
- Tempo: 96

Final treble staff:

```txt
Measure 1: C5 quarter, D5 quarter, E5 quarter, G5 quarter
Measure 2: E5 quarter, D5 quarter, C5 half
Measure 3: G4 quarter, A4 quarter, B4 quarter, C5 quarter
Measure 4: C5 whole
```

Final bass staff:

```txt
Measure 1: C3 whole
Measure 2: G2 whole
Measure 3: F2 whole
Measure 4: C3 whole
```

Required user mistakes during creation:

- Enter one wrong bass note, then repair it by dragging.
- Enter one extra treble note, then delete it through the notation UI.
- Skip one treble note, then use Insert mode/cursor to add it without rebuilding
  the rest of the passage.

Pass criteria:

- The grand staff score can be created from an empty score by browser interactions
  only.
- Treble and bass staff targeting is clear enough that a real user can place
  notes intentionally.
- Playback includes both staves in the expected order/timing.
- Exported PDF shows the grand staff clearly on A4.

## Ledger Stress Gate

The editor and PDF export must render these stress notes without clipping:

```txt
Treble low: C4, A3
Treble high: A5, C6
Bass low: C2, A1
Bass high: C4, E4
```

Pass criteria:

- Ghost notes and placed notes both show all necessary ledger lines.
- Noteheads are fully visible.
- Stems are fully visible.
- Ledger lines are fully visible.
- The same notes remain unclipped in exported PDF output.

## Browser QA Checklist

For each acceptance song:

- Start from Reset/New score.
- Use visible UI controls, not scripts.
- Add the required notes.
- Create and fix the required user mistakes.
- Save/load once if the step changes persistence.
- Playback the score.
- Export PDF after the backend export step exists.
- Record pass/fail notes in the step checkpoint.

## Final v0.5 Pass Criteria

v0.5 is complete only when:

- Treble melody browser QA passes.
- Grand staff browser QA passes.
- Ledger stress browser QA passes.
- Treble PDF export passes.
- Grand staff PDF export passes.
- Full automated test suite passes.
- Typecheck passes.
- Production build passes.
