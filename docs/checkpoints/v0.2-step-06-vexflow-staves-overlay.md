# V0.2 Checkpoint 06: VexFlow Staves With Interaction Overlay

## Goal

Replace the hand-drawn visible staff system with VexFlow-rendered treble/grand staves while preserving the existing editor interaction overlay.

## Acceptance Criteria

- The public `StaffRenderer` component renders through the VexFlow wrapper.
- Treble and grand staff systems display real VexFlow clef/time-signature glyphs.
- The transparent overlay still exposes stable test hooks for staff, barline, and grand-staff connector behavior.
- Hover ghost, event hit targets, selection markers, and playback playhead still render from the internal score model.
- Existing renderer tests and adapter tests pass.

## Test Plan

- Run `npm.cmd run test`.
- Run `npm.cmd run typecheck`.
- Run `npm.cmd run build`.

## Result

- Passed `npm.cmd run test`: 11 test files, 47 tests.
- Passed `npm.cmd run typecheck`.
- Passed `npm.cmd run build`.
- Added `src/features/sheet/VexFlowStaffRenderer.tsx`.
- Added `src/features/sheet/NotationOverlay.tsx`.
- Updated `src/features/sheet/StaffRenderer.tsx` to route through VexFlow.
- Updated `src/features/sheet/StaffRenderer.test.tsx` for the new renderer contract.

## Notes

- VexFlow emits jsdom canvas warnings during unit tests because jsdom does not implement real canvas text metrics. The tests pass, but this should be quieted later with a focused test setup mock.
- Production build passes, but Vite warns that the main JS chunk is large after adding VexFlow. This is accepted for this checkpoint and should be addressed in a later performance step with code splitting or lazy loading.

Passed.
