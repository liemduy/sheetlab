# Checkpoint: V0.2 Ghost And Placed Note Alignment

## Goal

Fix the core editor loop so the physical mouse position, ghost note, score hit target, and placed note all describe the same musical point.

## Root Cause Confirmed

- The first issue was vertical: VexFlow staff lines and overlay pitch geometry were not aligned.
- The second issue was horizontal/engraving: placed notes were rendered through VexFlow formatting, while ghost and hit targets used SheetLab's editor grid.
- The final browser repro showed a third issue: even when VexFlow metadata and bounding boxes reported the right center, the actual SMuFL text glyph could still look offset from the ghost.
- For direct manipulation, the editor grid must be the source of truth. Engraving spacing can become a later export/read-only layout mode.

## Changes

- VexFlow now renders only staff, clef, time signature, and barlines.
- Placed editor notes are drawn by the overlay layer using the exact same `getBeatX/getPitchY` coordinates as the ghost note.
- Regression tests now verify ghost, hit target, and actual placed editor notehead alignment.
- Browser screenshots before and after click are saved as QA artifacts.

- Browser: `http://localhost:5173/`
- Real action: scrolled horizontally to measure 3, moved the mouse to a visible staff line, clicked the same physical point.
- Before click: hover state reported `treble M3 B1 B4`; ghost reported `cx="493"` and `cy="114"`.
- After click: one placed editor notehead reported `cx="493"` and `cy="114"`; VexFlow event glyph count was `0`.
- Visual result: the black placed notehead is centered inside the green ghost/selection ring.

## Status

Passed. This checkpoint blocks future changes from reintroducing the mismatch between direct manipulation and rendered notation.
