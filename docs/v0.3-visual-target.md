# V0.3 Visual Target: Real Sheet Interaction

## Goal

Make the editor feel like a real sheet-music surface instead of a debug canvas.

The user-facing contract is simple: when the pointer hovers over the staff, the ghost note should look like the note that will be placed. After click, the placed note should replace that ghost at the same musical location.

## Reference Direction

- Classical printed sheet page.
- Centered title.
- Tempo marking on the upper left of the page content.
- Composer on the upper right.
- Staff systems with clean barlines and balanced white space.
- Piano grand staff should use brace and connected barlines.
- Editor feedback may use muted green, but the notation itself should remain black.

## Rendering Rules

- VexFlow owns staff, clef, time signature, brace, connectors, and barlines.
- SheetLab owns direct-manipulation editor notation: placed notes, ghost notes, rests, selection rings, hit targets, playback cursor, and ledger lines.
- Ghost notes and placed notes must use the same geometry and renderer.
- Ledger lines must appear for notes above and below the staff, including ghost previews.
- Selection and hover feedback must not make the note look misplaced.

## First Measure Input Rules

- Measure 1 has clef and time signature, but beat 1 must still be easy to place.
- The input region starts after the time signature, and hover should visibly snap to that first beat.
- Clicking in the clef/time-signature area should clamp to beat 1 instead of feeling dead when the pointer is vertically on the staff.

## Pass Criteria

- Opening the app resembles a basic sheet page.
- Hover looks like notation, not a generic marker.
- Click places a note exactly where the ghost preview was.
- Notes outside the staff show ledger lines.
- Measure 1 beat 1 is easy to discover and place.
- Browser screenshots before and after click pass visual inspection.
